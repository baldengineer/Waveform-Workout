Code structure

Three C modules connect the physical controls to the waveform at J2 and TP3. Follow a press of VALUE in the AMP row through the application.

  1. main.cReceive the press

    Zephyr debounces the key. on_key() queues its code. run_trainer() wakes and calls lesson_next_value().

  2. lesson.cSelect the amplitude

    The active row advances to its next value. lesson_sample() combines that amplitude with the saved shape and +0.75 V center to calculate each A/B pair.

  3. outputs.cApply the change

    outputs_apply() stops the old playback. start_analog() fills the existing buffer, primes both DACs, selects analog and starts TIM6.

The lights have their own timeout. After applying the change, the main thread lights the selected row and value. Two seconds later it sends a dark frame. Playback continues. Moving MODE between SHAPE, AMP and FREQ also preserves the running waveform.

Where to make a change

Presets and power-up state
The lesson header defines the six rows, one saved value per row, and the default 1 kHz, 1.00 Vpp sine. The host test exercises the settings, sample values, phase shifts and trigger widths. lesson.h · lesson_test.c
Pin assignments and peripheral wiring
The board description sets clocks and memory capacity. Its include files map DAC channels, selectors, buttons and the LED chain. The app overlay enables the timer pin states and assigns the two trigger DMA requests. Board DTS · Signals · Interfaces · App overlay
Build configuration
CMake selects the three source modules. The project configuration enables the Zephyr drivers. Kconfig provides a separate 250 kHz filter-test image. CMakeLists.txt · prj.conf · Kconfig

Signal playback

Analog waveforms and XY

A 13-entry quarter-sine table occupies 26 bytes in flash. The code mirrors it across quadrants to make a full sine. Integer arithmetic builds the square and triangle. It scales one cycle to the selected voltage and offsets B’s sample index for XY. All 48 pairs fit in the same 192-byte SRAM buffer.

A · DAC2 → J2Bits 27–16 · upper halfwordB · DAC1 → TP3Bits 11–0 · lower halfword

TIM6 latches both DACs together. DMA1 channel 2 writes the next word from samples[] to DAC1->DHR12RD at 0x40007420. At 1 kHz, 48,000 sample pairs per second give 48 updates per cycle. At 10 kHz the same buffer plays at 480,000 pairs per second. The CPU can sleep between control events.

DC and digital triggers

DC latches one fixed pair and leaves the sample timer stopped. TRIG selects the digital paths. Each 100 µs period, two TIM2 compare events request the next A pulse width and B marker width. DMA1 channel 1 writes A to TIM21->CCR1 at 0x40010834. Channel 4 writes B to TIM2->CCR2 at 0x40000038. The timers apply the widths at rollover. These peripheral addresses are hardware registers, outside the SRAM budget.

The long sequences need 1,000 periods to mark one narrow or missing pulse. The variable-width exercise repeats after just three periods. Both use the same two preallocated arrays.

What would save RAM?

Precomputing every analog preset in flash could recover at most the 192-byte DAC buffer if DMA played directly from those tables. The larger opportunity is the fixed digital trigger sequences. Moving both trigger tables to flash could reclaim 4,000 bytes, bringing the reservation to roughly 6,416 bytes (31.33%), assuming the rest of the layout stays the same. That is an estimate for a future build.

Build reference

These addresses describe the Rev 1 trainer image at firmware commit 33f2cfb. The separately linked filter diagnostic has its own layout. Byte counts come from the trainer’s final ELF and linker map. Changes to code, compiler options or Zephyr configuration can move the symbols.

Verify the map against a build

Build the trainer, then inspect build/trainer/zephyr/zephyr.map. Run arm-none-eabi-objdump -h on zephyr.elf for section sizes and load addresses. Run arm-none-eabi-nm -S -n on the same ELF for symbol addresses and sizes. Both tools show sizes in hexadecimal by default.
